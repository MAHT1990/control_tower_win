# 03. 사용자 유형 (User Type)

> 담당: plan_user_classifier · 깊이: light · 총 UT 1
> Control Tower는 인증 경계가 없는(C7) 로컬 단일 파워유저 도구다. v1은 로컬 전용·인증 없음이라 **현재** 사용자 유형이 UT-001 하나뿐이다. 본 문서는 그 유형을 정의하되, 인증·다중 사용자가 도입되는 후속 버전에서 유형이 확장될 수 있도록 UT 골격을 열어둔다.

---

## 0. 개요

### 0-1. 목적·범위

- **정의하는 것**: 현재 Control Tower를 쓰는 사람(UT-001)의 역할·목적·사용 맥락·핵심 니즈·권한.
- **정의하지 않는 것**
  - FR/NFR·기능 카테고리·제약은 [`04_requirements`](./04_requirements.md)가 확정한다. 본 문서는 그중 사용자 관점에 필요한 것만 **참조**할 뿐 재정의하지 않는다.
  - 세션·외부 프로세스는 **사용자로 다루지 않는다** — 앱이 제어·관측하는 *대상*이지 GUI를 조작하는 주체가 아니다. 구체적으로 (a) Claude Code / pwsh 세션은 UT가 부리는 제어 대상이고, (b) 앱이 소유하지 않은 외부 프로세스는 ConPTY attach 불가(C1)로 목록·주입·제어 어디에도 들어오지 않는다.
- **전제·확장 여지**: v1은 로컬 전용·인증 없음(C7)이라 사용자 유형이 UT-001 하나다. 인증·다중 사용자가 도입되는 후속 버전에서는 유형이 확장될 수 있으며, UT 발번 체계(0-2)가 UT-002+ 추가를 그대로 수용한다.

### 0-2. 표기 규칙

- **UT-###**: 사용자 유형 ID, 3자리 zero-pad. 본 문서가 발번한다. (현재 UT-001, 후속 버전에서 UT-002+ 추가 가능한 열린 체계)
- **카테고리·FR 인용**: 7개 기능 카테고리(TRM·SES·PRF·IPC·AST·SEC·SYS)와 제약(C1·C7)은 04가 freeze한 것을 **참조 전용**으로 인용한다. 재발번·재정의하지 않는다.

## 2. 사용자 유형 상세

### [UT-001] 단일 파워유저

- **역할**
  - 앱의 유일한 사용자이자 소유자
  - 세션 프로파일 관리
  - 세션 기동·주입·종료
  - IPC 채널을 통한 세션 간 협업
  - 프롬프트 자산(`~/.claude`) 편집
- **목적**
  - 흩어진 세션을 앱 하나에서 직접 띄우고 붙잡아 관리(앱-소유 완전 제어)
  - 세션끼리 채널로 묶어 여러 프로젝트를 동시에 굴리기(IPC 협업)
- **사용 맥락**
  - 일상적(작업 중 상주)
  - 고급 숙련(터미널·멀티세션에 익숙한 개발자, dogfooding)
  - Windows 11 / WPF·.NET 10 데스크톱
- **핵심 니즈**
  - 세션을 앱이 직접 띄우고 붙잡아 제어(앱-소유)
  - 세션끼리 서로 대화하게 묶어주기(IPC 협업)
  - 프롬프트 자산을 한 곳에서 고치기(통합 편집)
  - 자주 쓰는 조합을 저장해뒀다 바로 꺼내 쓰기(프로파일 프리셋)
- **권한**
  - 인증·역할 분리가 없으므로 7개 기능 카테고리(TRM·SES·PRF·IPC·AST·SEC·SYS) 전권
  - 별도 권한 조합·모드 구분 없음

---

## 3. 요약

- 사용자 유형 **현재 1개**: UT-001 단일 파워유저.
- v1은 로컬 전용·인증 없음(C7)이라 유형이 UT-001 하나이며, 그 사용자가 7개 기능 카테고리(TRM·SES·PRF·IPC·AST·SEC·SYS) 전권을 커버한다.
- 세션·외부 프로세스는 사용자가 아닌 제어 대상이다(0-1).
- 인증·다중 사용자가 도입되는 후속 버전에서 UT-002+ 로 유형이 확장될 수 있도록 골격을 열어둔다.
